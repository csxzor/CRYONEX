## 1. What this is, in one paragraph

**CRYONEX (Kill-Chain World Model)** is an offline AI system that watches network traffic (PCAP or
flow CSV), turns it into a "network state" every 10 seconds, and learns how that state evolves:
P(S_t+1 | S_t). It then **simulates the next 5 minutes** (30 steps) to estimate the
probability that an infiltration is coming. It maps the behaviour to **MITRE ATT&CK stages** (now and
next), explains **which traffic features drove the prediction**, and shows everything in a Streamlit
dashboard with two alert levels (⚠️ early warning, 🔴 attack in progress) and ATT&CK/D3FEND response
cards. It beats the required logistic-regression baseline, and it runs on a CPU laptop with no
cloud dependency.

**Naming (decided 2026-09-28):** the project is called **CRYONEX** (all capitals, matching the team name
CRYOBLUE) everywhere a person sees it: the dashboard, the docs, the deck and the CLI (`cryonex serve`).
Internal code identifiers deliberately keep the old name `kcwm`, so nothing breaks. That covers the Python
package `kcwm/`, `kcwm.pt` checkpoints, the model ID `"kcwm"` in `results/*.json`, and the `kcwm` command,
which still works as an alias.

## 3. How it works (pipeline)

```
PCAP ─► NFStream + raw IP-header plugin ─┐
CSV  ─► CIC / CTU-13 / DAPT readers ─────┴─► canonical flows ─► 10-s windows on the epoch grid
     (sessions split at gaps > 5 min; first 90 windows = warm-up; 64-window context)
  ─► 92 features per window (flow + packet + port/scan + lateral + C2 + exfil signatures)
  ─► warm-up normalisation (re-centred on each capture's own first 15 min: adapts to new networks)
  ─► World model: causal Transformer (d=96, 3 layers) → belief h_t
        explicit ATT&CK stage z_t (7 stages) + kill-chain progress p_t
        transition softmax(logA[z] + logB[p] + W_z·h), where A and B start from an ATT&CK prior
        latent dynamics MLP; binned (16 quantile bins) emission decoder = next-state distribution
        risk trained *through* the rollout, plus a direct-risk head (pre-registered fallback F-A)
  ─► analytic mean-field rollout over 30 steps (5 min) → P(infiltration by step k), stage marginals
  ─► Hybrid alert score = mean(Platt-calibrated world-model risk, Platt-calibrated gradient boosting)
  ─► Two-level alerts:
        Level 2 "attack in progress": hybrid ≥ threshold (3% FPR on calibration), 2-window hysteresis
        Level 1 "early warning": raw world-model risk ≥ threshold set on quiet benign calibration
                 windows at the early-warning budget (currently 5%), sustained 2 windows
  ─► Next ATT&CK stage = rollout^0.25 × learned transition table^0.75
        (table P(next | current, progress) counted on training labels, read at the model's own
         current-stage belief). 29% → 50% on real test stage changes.
  ─► Explanations: integrated gradients (native units), attention rollout, group counterfactual,
     host attribution (re-simulate without each host's flows) + flagged flows
  ─► Knowledge base: offline MITRE ATT&CK subset + D3FEND countermeasures (curated fallbacks marked)
  ─► Streamlit dashboard (kcwm/ui/app.py); also a CLI: cryonex forecast
```

The 7 stages are Benign, Reconnaissance, InitialAccess, LateralMovement, CommandAndControl,
Exfiltration and Impact. Their order is a contract: never reorder it (`kcwm/stages.py`).

## 4. Data

Raw data is read-only and lives in `~/Desktop/sih/data` (`paths.data_root`). **Never write to
`~/Desktop/sih`**, which is the old v1 project. Datasets downloaded for v2 live in this repo's
gitignored `data/raw/`.

| Dataset | Size used | Role |
|---|---|---|
| CIC-IDS2017, corrected CSVs + 5 raw PCAPs | 2.1M flows | primary; packet-level block merged from the v1 cache |
| CSE-CIC-IDS2018, corrected (6 of 10 days; 4 are corrupt) | 37.7M flows | breadth; cross-network target |
| CTU-13 (13 scenarios) | 20.0M flows | real botnet C2 → DDoS/spam cycles |
| DAPT2020 (Kaggle) | 0.09M flows | the only real APT chain (one stage per day, host 192.168.3.29) |
| DARPA 2000 LLDOS 1.0 / 2.0.2 (MIT LL, PCAP + phase lists) | 0.2M flows | **held out**; used only by the parked chain experiment |

That's about **60 million flows** in total. Processed outputs are in `data/processed/{flows,windows,campaigns,hosts}`.

* Label mapping: `configs/stage_map.yaml`, plus code rules. Lateral movement must originate
  inside the network; an external scan is Reconnaissance.
* Internal networks per dataset are set in `configs/default.yaml`.

**Splits and protocols:**
* **P1:** per-session temporal split, 60/15/25, purged. Dev mode uses the training tail for thresholds and
  the calibration span as the dev test.
* **P4:** synthetic kill-chain campaigns built from real snippets injected into real benign traffic of the
  same network and split. Reported separately, never pooled with real data.
* **G6:** leave-one-family-out.
* **G7:** cross-network.
* Test-split rules: see section 5.

## 6. Results (frozen model, P1 test, 3 seeds)

| Model | AUPRC | Precision | Recall | F1 | FPR |
|---|---|---|---|---|---|
| Logistic regression (PS baseline) | 0.650 | 0.832 | 0.363 | 0.505 | 0.036 |
| Gradient boosting | 0.767 | 0.786 | 0.529 | 0.632 | 0.070 |
| LSTM classifier | 0.769 | 0.818 | 0.441 | 0.572 | 0.048 |
| Transformer classifier (no dynamics) | 0.815 | 0.984 | 0.262 | 0.403 | 0.003 |
| CRYONEX world model alone | 0.820 | 0.861 | 0.614 | 0.711 | 0.052 |
| **CRYONEX hybrid (deployed)** | **0.847** | 0.894 | 0.620 | **0.725** | 0.042 |

* **Early warning (two-level, post-hoc):**
  * at the **5% budget (current config)**, 69/207 real attacks are warned before they start, with a median lead of 5.0 min and false early warnings on 3.2% of quiet time;
  * at 3%: 51/207, 3.5 min, 1.5%;
  * a sweep up to 20% is in BENCHMARKS.
  * About 20% of attacks have no precursor at all.
* **Next ATT&CK stage (post-hoc):** 29% → **50%** at 1 window before real stage changes (49% at 1 min).
  The ceiling, with the true current stage, is 58%. Knowing the *current* stage: about 79% on attack steps.
* **G6, unseen attack families:** hybrid 0.782 vs LR 0.569; wins all 7 families.
* **G7, new network:** partial. Ranking partly transfers; thresholds don't. There's a warm-up mode.
* **G8, explanations:** deleting the top-5 attributed features drops risk 500× more than deleting 5 random ones.
* **G3, learned dynamics:** the frozen model's next-state prediction beats persistence (NLL 1.84
  vs 2.41) and linear autoregression (2.74), **but loses to the recent 10-minute histogram (1.20)**.
  * A residual decoder (histogram × learned correction, `emit_prior=1`) wins at 10 s (3/3 seeds) and 1 min (2/3).
  * It is **not shipped**: it cut early warnings from 51 to 24 of 207, and it adds a false alarm to the Heartbleed demo.
  * The user decided to keep the frozen model. Its bundle is kept at `artifacts/kcwm-residual-decoder.pt`.
* **Demo sample** `samples/cic17_wednesday_heartbleed.csv.gz` (held-out part of Wednesday; the
  model never saw a Heartbleed attack):
  * true early warning ≈ 18:08, attack in progress 18:11, real exploit 18:12;
  * with the 5% budget there are also false early warnings ≈ 17:43–18:00 (at 3%, only ≈ 17:45–17:48).

**Honest limits to state if asked:**
* Early warning covers about 1 in 3 attacks, with a lead of minutes, not hours.
* Next stage is right about half the time.
* Multi-stage APT chains spread over days (DAPT) are not predicted.
* The model does not transfer cleanly to a brand-new network.

## 10. History, and decisions already made (do not re-litigate)

1. **Architecture choice:** a kill-chain world model (explicit stages plus a latent Transformer belief) instead of
   v1's RSSM+GNN. v1 lives in `~/Desktop/sih` and is read-only; its "what-if" heads were dropped.
2. **Dev rounds 1–6** (DEV_HISTORY): warm-up normalisation, campaigns, the direct-risk head, DAPT
   down-sampling, then the **hybrid**. Round 3 (early stopping on the training tail) was rejected.
3. **The final test was read once.** The user chose the hybrid as the deployed score.
4. **Two-level alerts** were added post-hoc: the world model carries the early-warning signal.
5. **Kaggle GPU experiments** (E1–E3, C1):
   * long-memory features gave slightly more early warnings but cost about 0.03 AUPRC, so they are off by default;
   * an extra early-warning loss weight was rejected;
   * the LSTM baseline comparison was de-emphasised at the user's request.
6. **Host kill-chain layer** (`kcwm/chain/`, DARPA 2000 ingest). It was built to answer "does it predict
   multi-stage APT progression?" The answer is mostly **no** on unseen networks:
   * per-host stage recognition fails there (it recognises 8–15% of attack activity);
   * next-stage accuracy is about 10% on the DAPT and DARPA held-out chains;
   * with true history it would work (dev 0.56 vs lookup table 0.50).

   The user said **no stretch goals**, so this is **parked**: its dashboard panel hides itself when there's no `chain.joblib`.
   Suggested: move it to a separate git branch.
7. **G3 dynamics:** the gate was never run on the frozen model until now. The residual-decoder fix proves learned dynamics,
   but costs early warning, so the user chose to **keep the frozen model**. Both are documented in BENCHMARKS §7.
8. **Next-stage blend** (29% → 50%) and the **5% early-warning budget** (51 → 69 of 207 warned) were adopted.
   Still pending: the user may revert to 3% for a cleaner Heartbleed demo (see section 12).
9. **The deck** was rebuilt from the user's rough draft. Real measured numbers replaced the draft's invented targets
   (95%/92%/…).

## 13. Gotchas that cost time before

* **RAM:** 15 GB. `/tmp` is tmpfs, so files there eat RAM; the Claude scratchpad lives in `/tmp` too.
  Big jobs were OOM-killed (exit 137) until the chain pipeline loaded only the hosts it tracks.
* **Background jobs:** a `cmd &` started inside a tool call dies with that shell; use a real background run.
  `pgrep -f <pattern>` inside a wait loop matches its own command line, so wait on a PID instead.
  Output needs `PYTHONUNBUFFERED=1`.
* **Feature count:** the code registry has 116 features (with history); the frozen models use 92. Anything
  that loads a checkpoint must use the bundle scaler's names (`arrays_for` in `scripts/g3_dynamics.py`).
* **Time zones:** DARPA 2000 lists are US Eastern *local* time (EST in March, EDT in April). CIC-2017 uses UTC in the processed data.
* **The streamlit dashboard caches the bundle.** Restart it after rebuilding `artifacts/release/kcwm.pt`.
* **LibreOffice** is installed as a user Flatpak (about 1.5 GB), for rendering slides:
  `flatpak run org.libreoffice.LibreOffice --headless --convert-to pdf …`.
  Remove it with `flatpak uninstall --user org.libreoffice.LibreOffice`.
* **Kaggle:** Python version mismatch, so the runner uses `PYTHONPATH`, not `pip -e`. Build the package with
  `scripts/make_kaggle_package.sh`.
